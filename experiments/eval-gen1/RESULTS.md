# Eval gen1: feature-set A/B (bands, king-split) on gen1 data

Base: `t3/optimize-checkers-engine` @ 9e4b4e0. The weights in this directory are **not** installed;
`src/weights/eval.bin` (gen0) and the CMake defaults are unchanged on this branch.

| File | CMake options | Features (`features::COUNT`) |
|---|---|---|
| `w_V1.bin` | default (`REGICIDE_EVAL_BANDS=OFF`, `REGICIDE_EVAL_KINGSPLIT=OFF`) | same layout as gen0 |
| `w_B.bin`  | `-DREGICIDE_EVAL_BANDS=ON` | + 7 two-row bands |
| `w_K.bin`  | `-DREGICIDE_EVAL_KINGSPLIT=ON` | + second window set while kings are on |
| `w_BK.bin` | both ON | both |

Each file loads only in a build with matching options (the feature count is checked).

## Data

- `gen1_n10k.bin`: 9,643,008 positions.
- `gen1b_snap.bin`: 3,952,896 positions. This is the complete prefix of `gen1b_n10k.bin` at
  2026-11-07 14:27 CET, while datagen was still running (sha256 `0acbafbe26185748290ef203637b131c2954a7a0944ffce7c64b5568aa9235de`).
- Train / valid split: 13,323,986 / 271,918 positions (trainer seed 7, 2% valid). The fitted K is 99.0.

## Training

```
train --data gen1_n10k.bin --data gen1b_snap.bin --out w_<v>.bin --epochs 8 --lr 0.01 \
      --batch 65536 --lambda 0.7 --threads 4          # default l2; ~1 min each
```

| Weights | final train loss | final valid loss |
|---|---|---|
| gen0 (built-in, evaluated on the same valid set) | – | 0.537099 |
| init (material only, epoch 0) | – | 0.537933 |
| V1 | 0.536082 | 0.535949 |
| B  | 0.535803 | **0.535674** |
| K  | 0.536113 | 0.535978 |
| BK | 0.535832 | 0.535701 |

Full logs are in `logs/`. As a control, V1 was also trained at lr 0.1 and lr 2.0 (the trainer's own
default). In both runs the loss gets worse every epoch: the final valid loss is 0.543297 at lr 0.1
and 0.545739 at lr 2.0. lr 0.01 is the right setting for this data and batch size.

## Matches

- Engines: one `regicide_cb` `.so` per variant, built with that variant's options and its weights
  compiled in. G0 is the default build with the gen0 weights.
- Runner: `tools/match` with `cbhost` on Linux (WSL2, clang 22, `-march=native`, Core Ultra 9 285K).
- Time control: `--movetime 0.1` (CheckerBoard bank rules), `-c 10`.
- Engine settings: `set threads 1`, `set hashsize 128`, `set book 0` for both engines.
- Endgame database: the same 2–6-piece database for every engine (`~/regicide-data/egdb`). It is
  provided as an `egdb` symlink next to the `.so` files, because `set dbpath` cannot work here (see
  Notes).
- Openings: `openings4.txt`, all 805 distinct positions after 4 plies (generated by
  `scripts/gen4.cpp`). Each is played with both colours, so a pairing is 1,610 games.

Elo, the 95% interval and LOS are from the pentanomial model (game pairs):

- **How match nps was measured:** total nodes divided by total search time, over every move with at
  least 10k nodes, read from the `--pdn-comments` engine output (`scripts/nps.py`).
- **Why the absolute nps differs between rows:** machine load changed between matches; 12 datagen
  threads were running for part of the time. Only the ratio within a row is meaningful.
- **Noise floor:** V1 and G0 have the same feature set, yet their match nps differs by 1.3%. Treat
  differences of about 1% as noise.

Single-thread `regicide bench 16`, three runs each (datagen running on 12 other cores):

The bench positions show no measurable cost from the extra features. In real games the bands cost
about 3–4%.

Per-pairing `summary.txt` and `results.csv` files are in `matches/`. The PDNs (about 16 MB each)
were left out of the commit.

## Conclusions

1. **gen1 data:** V1 is gen0's feature set retrained on gen1 + gen1b, and it beats gen0 by
   **+68 Elo**.
2. **Bands:** a significant gain. B beats V1 by **+11 Elo** (LOS 99.5%), even though B is about
   3.5% slower. B is the strongest variant: **+77 Elo vs G0**.
3. **King-split:** no gain and probably a small loss. K is −7 vs V1 (LOS 4.5%), and its valid loss
   is no better than V1's.
4. **BK:** +8.6 vs V1, no better than B alone (+11.2). Against G0, BK's +66 is below B's +77, though
   the two confidence intervals overlap.

**Recommendation:** adopt BANDS=ON and leave KINGSPLIT off, using the weights in `w_B.bin`.

## Notes

- **egdb load bug:** the CB API's `set dbpath` cannot load a database in practice. `egdb::init` is
  `std::call_once`, and engine start-up has already called it on `<library dir>/egdb`. If that
  directory is missing, every later `set dbpath` returns the cached failure (`src/cb_api.cpp`
  `load_egdb`, `src/egdb/store.cpp` `init`).
- **Book off:** the built-in book was turned off for every engine, so book moves cannot hide eval
  differences out of the 4-ply openings.

Reproduce: `scripts/gen4.cpp` (openings), `scripts/runmatches.sh A:B ...` (runner), `scripts/nps.py games.pdn`.
