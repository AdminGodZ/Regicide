# gen2: linear eval retrained on gen1 + gen2a (97M positions), a44591e trainer

All binaries were built from `master` @ `a44591e` (Release, clang 22, `-march=native`, WSL2, Core Ultra 9 285K). Its
built-in eval is `w_lr0.03_wd0` (`experiments/gen1full/wd/w_lr0.03_wd0.bin`, called "built-in" below).

## Data

| File | Positions | Eval used by datagen |
|---|---|---|
| `gen1_n10k.bin`  |  9,643,008 | gen0 built-in (b71dfa9) |
| `gen1b_n10k.bin` | 29,817,546 | gen0 built-in (b71dfa9) |
| `gen1c_n10k.bin` | 29,816,510 | gen0 built-in (b71dfa9) |
| `gen2a_n10k.bin` | 30,060,997 | B13 (2732f0d) |

Train / valid split: 97,351,300 / 1,986,761 positions (trainer seed 7, 2% valid). The fitted K is 108.7.
This split is different from the gen1full split (3 files, K 98.6), so the losses below are not comparable with
`experiments/gen1full/RESULTS.md`.

## Training

```
train --data gen1_n10k.bin --data gen1b_n10k.bin --data gen1c_n10k.bin --data gen2a_n10k.bin --out w_<run>.bin \
      --epochs <E> --lr <lr> --batch 65536 --lambda 0.7 --l2 0 --l2-table 0 --wd 0 --wd-table 0 --threads 12
```

The built-in eval was scored on the same split with `--init experiments/gen1full/wd/w_lr0.03_wd0.bin --epochs 0`
(`logs/train_builtin_e0.log`). The runs went one after another (21:37 to 21:56, about 27 s per epoch) on an
otherwise idle machine. The lr schedule is the trainer's: x1 for the first third of the epochs, x0.3 for the second
third, x0.1 for the last third.

## Matches: G2d and G2c vs the built-in

The two runs with the lowest valid loss, G2d and G2c, both beat the built-in's loss. Each was compiled into a
`regicide_cb` `.so` (weights copied to `src/weights/eval.bin` in a scratch worktree of a44591e). Each `.so` was checked
to contain its own weights and no other run's weights. The match settings are the same as for W_lr0.03_wd0 vs B13 in
`experiments/gen1full/RESULTS.md`:
- Runner: `tools/match` + `cbhost`, `--movetime 0.1`, `-c 10`.
- Engine settings: `set threads 1`, `set hashsize 128`, `set book 0` for both engines.
- Endgame database: 2-7 pieces, via an `egdb` symlink next to the `.so` files.
- Openings: `openings4.txt`, 805 positions x both colours = 1610 games.

| A vs B | Elo [95% CI] (pentanomial) | LOS | W / D / L | pairs LL LD DD+WL WD WW |
|---|---|---|---|---|
| G2d vs a44591e | **+11.2** [+5.5, +17.0] | 99.99% | 338 / 986 / 286 | 0 / 67 / 619 / 119 / 0 |
| G2c vs a44591e | **+14.3** [+8.5, +20.0] | 100.00% | 354 / 968 / 288 | 0 / 61 / 619 / 123 / 2 |

Both candidates are stronger than the built-in eval. The difference between G2c and G2d is well inside the noise.
**G2c has the higher point estimate, so it is the gen2 winner** (`w_G2c.bin`).

Machine load during the matches: the plan was to run them while gen2b datagen kept going. They ran later, on an
otherwise idle machine:
1. The first attempt (23:39, right after the baseline) failed at once. The match binary had been copied to a
   directory without `cbhost` next to it (`FATAL: cannot start .../cbhost`), and no games were played.
2. The PC lost power at about 23:45.
3. The matches were rerun from scratch at 00:20 (G2d) and 00:35 (G2c), with `cbhost` copied next to the binary.
   gen2b datagen had finished at 23:15, so it was **not** running during the matches. A `pip install` of PyTorch
   (`nice 19`, mostly download) ran during the G2d match.

## gen2b datagen (a44591e built-in eval)

```
datagen --games 300000 --nodes 10000 --threads 12 --seed 37 --out gen2b_n10k.bin     # a44591e, built-in, no --evalfile
```

21:56 to 23:15 (79 min). Most of that time it ran alongside the baseline matches. Output: `gen2b_n10k.bin`,
**288,205 games, 29,516,347 positions** (472,261,552 bytes = 16-byte records exactly). 300,000 games were attempted.
datagen drops a game whose random opening scores beyond `max_opening_score` in a 2000-node check search. With the
new eval that happened to 3.9% of the openings, compared with 0.5% for gen2a (B13). The file was checked after the
power loss: the size is a multiple of 16, there are no zero records at the end, and the log says `done:`.
